# 차량 탑승자 안전 확장안

기존 긴급신고·상담·신고 후 대기 흐름에 **차량 안의 위험 환경 확인 → 짧은 음성 질문 → 전문 도움 → 전달 요약**을 잇는 제안이다. 이번 결과물은 설명자료·화면안·센서 기획이다. 차량 실내 온도·CO₂·CO·잔류 감지 Provider나 이를 이용한 자동 신고 코드를 앱에 추가하지 않았다.

[24장 PPTX/PDF와 제작 소스](presentation/scenario-safety-20261115/README.md)는 현재 기능과 제안을 구분한다. 이전의 반복 하단 문구와 사용자가 삭제 요청한 네 문구를 제거했다. 앱 자체의 실행·개인정보·기관 연결 정책은 유지한다.

## 다루는 상황

| 상황 | 현재 흐름 | 확장할 기능 |
|---|---|---|
| 사고·부상 | 기관 연결 화면, 차량·위치 요약, 음성 상태 확인 | 승인 사고 신호·실제 기관 연계 |
| 응급처치 상담 | 119 응급상담 진입, 전달 자료 | 실제 통화 플랫폼 연계 |
| 콜백·출동 대기 | 사용자 확인 상태, 악화 재신고 안내, 인계 요약 | 공식 상태 수신 |
| 차량 내 자살 위기 | 109 마음상담 연결 화면 | 전문가 검토를 거친 안전 확인·위기 지원 |
| 혼자 탑승·고립·무응답 | 시작한 응급 세션의 상태 확인 | 존재·환경 신호 확인, 사전 동의 보호자 알림 |
| 폭염·고온 노출 | 사용자가 119 요청·기본 대기 지원 가능 | 실내 온도·상승 추세·습도 경고 |
| 주차 후 아이 잔류 | 사용자 신고·가족정보 활용 | 제조사 잔류 감지·저전력 서비스 연계 |
| 차박·캠핑 중 공기질 | 사용자 신고·현재 위치 전달 | CO₂와 CO를 별도 측정·경고 |

혼자 있거나 답하지 않는다는 사실로 자살 의도·질환·사망을 판단하지 않는다. ‘차량 고독사’는 이 자료에서 차량 내 고립·무응답 상황에 대한 예방 지원 맥락이며, 사망 원인을 특정하거나 법적 분류를 확정하는 용어로 쓰지 않는다. 심리적 위기와 열·가스·질환에 따른 신체 응급상황의 경로를 나눈다. 특정 자해 수단이나 방법에 관한 내용은 제공하지 않는다.

## 온도와 HVAC

Pleos 공식 Vehicle SDK 2.3.2 안내에 HVAC 도메인과 온도 API가 있다. 현재 프로젝트의 `PleosEmergencyVehicleProvider`는 기존 도어·배터리·에어백 어댑터를 재사용하며 실내 온도를 읽지 않는다. 실제 탑승자 위치의 실내 측정인지, 영역·단위·측정 시각·권한·차종 지원이 무엇인지는 추가 검증해야 한다.

냉방 설정 온도, 외기 온도, 실제 실내 온도와 사람의 체온을 구분한다. 자료의 42°C·5초 표시는 **가상 화면 예시**다. 이를 열사병 진단·범용 경보 임계값·안전 노출 시간으로 사용하지 않는다. 온도·상승속도·습도·탑승자 존재·운행 상태를 조합한 규칙과 경보 조건은 제조사 및 전문가 검증을 거쳐야 한다.

정차 상태를 확인한 후의 질문 예시는 “차 안이 많이 덥습니다. 안전하게 내릴 수 있나요?”다. 주행 중이면 안전한 정차 안내를 우선하고 화면 입력을 요구하지 않는다. 의식 저하·심한 증상·스스로 벗어나기 어려움에는 119 도움을 우선하도록 설계한다. 특정 냉방·창문·도어 제어는 현재 기능에 포함하지 않는다.

## CO₂와 CO는 별도 측정

전용 센서가 있으면 CO₂ 농도를 측정할 수 있다. NDIR 같은 방식은 측정 후보이며, 단순 온도·스마트폰 마이크로 농도를 계산했다고 표시할 수 없다. CO₂는 환기를 살피는 참고값이지만 낮은 CO₂가 다른 가스에 대한 안전을 증명하지 않는다. 건물 환기 안내의 ppm 값을 차량 경보 임계값으로 그대로 가져오지 않는다.

CO는 CO₂와 다른 일산화탄소이며 급성 중독 위험을 별도로 다뤄야 한다. 전기화학식 등 전용 센서와 독립 경보가 후보이다. 일반 VOC·미세먼지 센서의 값을 두 가스의 직접 농도로 취급하지 않는다. 가스 센서의 수명·보정·교차 감도·온습도 영향·장착 위치와 차량용 안전 검증이 필요하다.

## 센서와 서비스의 우선순위

1. 실내 온도·습도와 유효한 측정 시각: 가장 먼저 경고 UX를 검토한다.
2. mmWave 등 잔류 존재 신호와 좌석·벨트·도어 맥락: 한 신호로 빈 차를 확정하지 않는다.
3. CO₂·CO 전용 센서: 가스별 단위·고장·보정 상태를 별도 관리한다.
4. 시동 종료 후 저전력 감시·전원·원격 통신: 일반 앱의 실행 상태만으로 상시 감시를 보장하지 않는다.

현대차 일부 차종의 Advanced Rear Occupant Alert처럼 이미 제공되는 보호 기능과 협력한다. 잔류 감지 자체를 새로운 발명이나 현재 LifeLink 통합 기능으로 소개하지 않는다. 제안하는 가치는 경고 이후 반응 확인·도움 요청·가족 건강정보 전달·대기 지원을 잇는 경험이다.

## 데이터·AI 구조

기존 `Evidence<T>`의 출처·시각·미지원·확인 불가 표현을 재사용할 수 있도록 `CabinEnvironmentProvider`를 별도 설계하는 방향이다. 실제 Provider는 승인 SDK/센서 어댑터, Mock은 가상 시연 입력으로 분리한다. 필요한 짧은 구간만 메모리에 유지하고 고장·미수신·오래된 값을 정상으로 채우지 않는다.

LLM은 질문 표현·제한된 의미 코드·요약을 보조한다. 환경 경보 규칙, 의학적 기준과 위기 개입 절차를 자유 생성하게 하지 않는다. 위험 안내는 검토된 고정 콘텐츠를 사용하고 통화 중 TTS/STT는 멈춘다. 센서 경고·정신건강 전용 절차는 기존 임상 콘텐츠와 별도로 전문가 검토가 필요하다.

보호자 원격 알림의 사전 동의·대상·철회는 목적에 맞게 설계하며 기존 외부 LLM 동의로 대신하지 않는다. 실제 기관 자동 신고·콜백 예약·출동 확정은 공식 연계가 있을 때만 표시한다. 미연결 상태에서도 사용자가 직접 도움을 요청하는 경로는 열어 둔다.
