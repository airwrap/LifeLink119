# 밝은 조작 영역과 전체 매뉴얼 · v0.17.0

검증일: 2026-11-07. minSdk 28 / compile·target 34 / Vehicle SDK 2.3.2. 배경과 버튼이 모두 어두워 조작 영역이 구분되지 않는 문제를 개선했습니다.

## 검토와 방향

실제 기존 첫 화면을 촬영한 뒤 공통 Kotlin 스타일·버튼 생성 함수·기본 대화상자 테마를 대조했습니다. 기존 버튼 #3E4754는 페이지 배경 #191C22와 대비가 1.82:1이었습니다. 글자는 충분히 읽혀도 누를 수 있는 면이 잘 드러나지 않았습니다. 기본·누름·포커스·비활성 상태를 함께 바꿔야 했고, 밝은 면에는 짙은 글자를 별도로 지정해야 했습니다.

- 제품: 가족의 긴급 요청과 상담, 선택적 건강정보 관리를 돕는 차량형 앱.
- 성격: 차분함·분명함·배려.
- 환경: 어두운 차량 패널과 쉽게 구분되는 밝은 조작 면.
- 중요한 순간: 도움 종류 선택, 연결 상태, 동의와 철회, 인계와 종료.
- 고유 단서: 동일한 비중의 네 홈 메뉴와 빨강 119·파랑 112 식별.

사용자가 전체 버튼을 밝게 해 달라고 지정한 방향을 적용했습니다. 기존 기능 순서와 96dp 조작 기준, 의료정보 보호, 실제 CarUX 제한을 유지합니다. 이미지 장식이나 새 UI 프레임워크는 추가하지 않았습니다.

## 실제 확인

- **최종 빌드·단위 테스트 166개·lint 통과**. lint `No issues found`.
- 표준 Android 34 네이티브 회귀 **9개 그룹 통과**. 가운데 정렬·96dp·잘림·동일 홈 비중·동의/철회·추가 제한·의료정보 캡처 거부·큰 글씨/520dp 미리보기를 확인했습니다.
- 캡처에서 검사한 버튼 대비 **112개 표본, 최소 7.289:1**. 활성 버튼 바탕과 페이지 배경 대비도 별도로 검사했습니다.
- **1280×720·1024×600 실제 ADB 터치 통과**. 앱을 계측하지 않는 실제 접근성 트리의 좌표로 119를 눌러 가상 응답을 확인했습니다. 네 홈 버튼과 연결 후 네 주요 동작이 화면 안에 들어옵니다. 화면 크기는 원래 값으로 복원했습니다.
- **공개 화면 40개를 동일 APK에서 재촬영**했습니다. 촬영 후 크기를 복원했고 PIN·개인 의료기록을 입력·수정·삭제하지 않았습니다.
- 공식 Pleos SDK 값 비교는 [동일 APK 검증 요약](manual/v17/sdk-verification.json)으로 구분합니다. 공식 Console의 가상 입력을 실제 앱 Gateway/SDK 반환값과 비교합니다. 표준 Android의 예시 화면을 SDK 성공으로 처리하지 않습니다.

초기 화면 크기 검사에서는 Android 기본 Pixel Launcher의 ANR과 계측기 Activity 참조 전환 문제가 있었습니다. 해당 실패 기록을 남기고, 정상 UI의 ‘Close app’으로 멈춘 런처를 정리한 뒤 앱을 계측하지 않는 실제 화면/터치 경로로 두 해상도를 다시 통과했습니다. 앱의 터치 가림 방지나 의료정보 보호를 끄지 않았습니다.

SDK 검사에서는 cold boot 직후 getter가 먼저 동작하고 Console 게시자가 늦게 준비되는 경우를 구분했습니다. 읽기 값만 보고 변경 검사까지 통과시키지 않습니다. 필요한 게시자의 준비를 최대 120초 기다리고, 준비 실패는 차단으로 기록합니다. 설치는 시간 제한이 있는 push+PackageManager 방식으로 보완했습니다. 차량 제어 권한·root·CarUX 우회·네트워크 권한 상승을 추가하지 않았습니다.

실제 차량 주야간 시인성·운전 중 사용성·회전 조작기·사람에 의한 스크린리더 평가는 이번 검사 범위에 포함하지 않습니다. Pleos 패널의 전체 UI 자동 회귀와 표준 Android의 UI 회귀도 구분합니다.

최종 자료 검증 후 에뮬레이터를 홈 화면으로 복원하는 과정에서는 Android의 `Process system isn't responding` / `System UI isn't responding` 오류가 반복됐습니다. Android 재부팅과 데이터 삭제 없는 cold start로도 마지막 홈 복원을 확인하지 못했습니다. 앞서 통과한 네이티브·실제 터치·SDK 검사 및 촬영본과 이 후속 실행 환경 오류를 구분합니다. 검증용 에뮬레이터 실행은 정상 종료하고 AVD·앱 데이터를 보존했습니다. 현재 PC에서 다시 시연하기 전에는 에뮬레이터 시스템 UI 상태를 점검해야 합니다.
