# 주행 중 긴급 호출 시연 · v0.7

**시연 모드 | 실제 신고·상담 연결 아님**

정차 전에 도움이 필요한 **차 안의 위급 상황**을 D01로 추가했다. 위험 종류를 고르는 메뉴 없이 119 상황실에 먼저 연결한다. 실차 없이 Pleos API 34 에뮬레이터에서 실행한다. 실제 발신·녹음·음성 인식·GPS 수집·차량 제어·기관 접수는 없다. 실제 사건의 위치·인물·차량정보도 사용하지 않는다.

## 발표 순서

1. 홈 상단 **119 빠른 호출**을 누른다. 등록·PIN·정차·위치 확인 없이 가상 연결을 요청한다. 반복해서 누르면 진행 중인 같은 호출로 돌아간다.
2. **가상 상담원 응답**을 확인한다. ‘주행 중’은 시연 상태이며 실제 차량 센서 측정값이 아니다.
3. 위험 종류를 선택하는 문답은 없다. **차 안의 위급 상황**으로 요청하고 구체적인 내용은 연결 후 상황실에 설명하는 흐름이다. 위험 자동 감지는 없다.
4. **확인한 상황 전달 · 모의 → 상황실 역할 · 내용 확인**을 누른다. 위치를 몰라도 상황 전달은 가능하다. 인원·부상 여부는 미확인으로 두며 임의 진단하지 않는다.
5. 필요한 경우에만 **가상 위치만 공유 / 가상 차량 정보만 공유**를 선택한다. GPS가 아닌 DEMO_GRID이며 의료정보는 기본 비공유다. **공유 철회**로 제거한다.
6. **안전한 곳에 정차했다고 알림 → 안전 확보했다고 알림**을 시연자가 입력한다. 이 입력은 실제 차량 정차 판정·제어가 아니다. 정차 전 호출·상황 전달이 먼저 가능하다.
7. 상황실 확인과 안전 확보가 모두 완료되면 **가상 대응팀 인계 확인 → 시연 완료·공유정보 정리**로 끝낸다. 중간 취소도 가능하다.

음성 진입 예시는 **더보기 → 설정·시연 도구 → 주행 중 긴급 호출 시연 → 음성 요청 예시 실행**에서 보여준다. 정해진 문구의 버튼으로 요청을 재현하며, 실제 음성 인식이나 무조작 호출이 구현됐다고 설명하지 않는다.

## 전체 서비스와의 연결

- 기존 두 가지 홈 행동, 119/112/109 목적별 연결과 가족정보 보호를 유지한다. D01은 19번째 갤러리 예시다.
- D01의 **기존 추가 지원 보기**에서 기존 수어·문자·기본 매뉴얼·주변 차량 협력 흐름으로 이어진다. 의료정보는 기존 인증과 항목별 동의를 거친다.
- 주변 차량 초대·수락·임무 부여와 119/112 역할의 표시 승인 절차는 각각 별도다. 긴급 호출만으로 등화 표시나 협력 승인이 발생하지 않는다. 표시도 화면 모형이다.
- 앱 내 가상 상황실은 오프라인이다. 선택적인 PC 상황실 전송은 기존 스키마의 상태·공유 항목 이름만 허용한다. D01의 전달·안전 확인은 앱에서 시연하며 PC에는 추가 전송하지 않는다.
- 실제 CarUX 제한은 그대로 적용한다. 제한 중 빠른 호출은 남기되 상세 역할 조작·음성 예시 설정·긴 목록은 제한한다. 수동 ‘정차’ 입력은 제한을 해제하지 않는다. OEM의 실제 실행 허용 여부를 인증한 결과는 아니다.
- 화면 복원 시 호출은 유지하고 전달·안전 확인은 초기화한다. 현재 상황을 재확인하라는 안내를 표시한다. 종료하면 해당 상태와 공유정보를 정리한다.

## 실패와 대안 시연

- 설정·시연 도구의 **다음 연결 실패 시연**을 켠 뒤 빠른 호출: 실패 → 같은 호출 다시 시도 → 가상 응답. 취소도 가능하다.
- **가상 위치 사용 가능**을 끄는 시연: 위치 버튼은 비활성화되지만 호출·상황 전달·인계는 가능하다.
- 추가 제한 시연: 빠른 호출 유지, 상세 패널 제한, 종료 가능. 실제 플랫폼 제한보다 느슨하게 만들지 않는다.
- 공유 철회, 앱 전환, 중복 호출, 다른 가상 상황 선택, 완료 후 재시작을 점검한다.

## 안내 근거와 구현 경계

[소방청 119 구급신고 요령](https://www.nfa.go.kr/nfa/safetyinfo/emergencyservice/119emergencydeclaration/)의 확인 가능한 상황 전달 원칙을 참고했다. 구체적인 위험에 관한 자가 판단을 선행시키지 않는다. 대피 위치·이동 방법은 현장 여건과 실제 상황실 지시를 우선한다.

이 버전의 정차·안전 확보·인계는 모두 시연자의 명시적 입력이다. 실제 출동, 자동 감지, 실시간 음성 상담, 자동 안전 판단, 도로에서의 차량 표시를 구현한 것으로 제시하지 않는다.

## 재검증

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain --no-parallel --max-workers=1 *> build-driving-v07-final.log
python -m unittest discover -s console -p 'test_*.py' *> console-driving-v07.log
python scripts/prepare-native-window.py --serial emulator-5580
python scripts/smoke-driving-emergency.py --serial emulator-5580
python scripts/verify-driving-artifacts.py
```

JDK 17·API 34·build-tools 35.0.0과 선택한 전용 에뮬레이터가 필요하다. 빌드 APK를 먼저 해당 에뮬레이터에 설치한다. 재현 스크립트는 별도 테스트 패키지로 설치 APK의 실제 View를 조작한다. 보호된 의료정보 화면의 캡처는 FLAG_SECURE 검사로 거절한다. 실제 발신이나 의료정보 인증은 수행하지 않는다. 검증 결과는 로컬 `verification/v07/`에 생성한다.

## 이번 PC에서 실행하기

Android Studio Device Manager에서 **LifeLink119_Verify_20261101**을 실행하고 앱을 연다. 이 AVD는 같은 공식 Pleos API 34 이미지로 별도 생성한 검증 환경이며 최신 APK가 설치되어 있다. 기존 Pleos_Connect_API_34의 데이터 파일은 검사 전 상태로 복구했다. 새 PC에서는 기존 가이드에 따라 새 Pleos AVD를 만든 뒤 APK를 설치하면 된다.
