# 우리 가족 안심콜과 건강정보 · v0.10

## 앱 안에서 가능한 것

- 홈의 `우리 가족 안심콜`에서 본인 인증 또는 사용자가 설정한 PIN을 거쳐 내 건강정보를 열 수 있다. 개인정보가 없어도 119 요청은 가능하다.
- 이름, 병력, 알레르기와 투약 내역을 사용자가 직접 입력하여 기기에 저장·조회·수정·삭제한다. 투약 내역은 사용자가 직접 적은 기록이며 의료기관의 처방전이나 자동 수집 내역이 아니다.
- Android Keystore의 AES-GCM 키로 암호화해 저장하고, 의료정보 화면에 `FLAG_SECURE`를 적용한다. 자동완성과 입력 뷰의 상태 저장을 끄며 로그와 세션 저장 상태에 내용을 넣지 않는다. 기존 가상 가족 예시·가상 상황실 공유 데이터와 분리한다.
- 홈 복귀·앱 전환·인증 만료 시 잠그고, 잠금 초기화 시 개인 건강정보도 삭제한다. 직접 입력 정보는 119, 가상 상황실, 다른 기기로 전송되지 않는다.

## 공식 연계 상태

현재 앱은 **소방청 119 안심콜과 연결되지 않았다**. 앱에 입력했다고 공식 안심콜에 등록되거나 119에 제공되는 것이 아니다. [소방청 119 안심콜 안내](https://nfa.go.kr/nfa/safetyinfo/emergencyservice/urelaxcallservice/)

**건강정보 고속도로에도 연결되지 않았다**. v0.11부터 가입 동의와 고정된 가상 투약 내역을 보여주는 예시 화면이 있으며 실제 조회 결과가 아님을 표시한다. [공식 API 안내](https://myhealthway.go.kr/portal/index?page=Organization%2FPortal%2FMediMyData%2FMydataApi)와 [정보 종류](https://www.myhealthway.go.kr/portal/index?page=Individual%2FPortal%2FMediMyData%2FMydataType)를 기준으로, 향후 실제 연계 시 참여 절차와 접근 자격을 운영기관에 확인하고 본인 인증·세부 동의·동의 철회·항목과 기간·전송 이력·출처·갱신일·오류 처리를 설계해야 한다. 앱에는 API 자격증명이나 실제 조회를 넣지 않았다.

요청된 [2025년 정책브리핑 기사](https://www.korea.kr/news/policyNewsView.do?newsId=148940518)는 본인의 개인정보를 본인 또는 마이데이터 사업자에게 전송하도록 요구할 수 있는 제도를 설명한다. 기사 자체가 이 앱의 119 연계나 즉시 API 접근을 보장하지는 않는다.

공모전용 개발 빌드다. 실제 의료정보 처리·상용 배포 전에 별도의 개인정보 영향, 사용자·의료진 검토, 키 관리 및 기기 분실 대응, 보안 검증과 관계 기관 협의가 필요하다.

## 검증

- 최종 APK 빌드와 JVM 단위 테스트 147개, Android lint 통과. `verification/v10/build-final.log`, `verification/v10/lint-final.log`.
- 전용 에뮬레이터에서 임시 PIN과 가상 입력값으로 인증 전 차단, 암호화 저장, 홈 복귀 후 재인증 및 조회, 삭제, 잠금 중 119 요청을 확인했다. 테스트 PIN과 가상 입력은 종료 시 삭제했다. 결과: `verification/v10/personal-health.json`.
- 119·112·119 상담·109 경로, 영상 동의와 철회, 백그라운드, 주행 제한 및 520dp 미리보기의 7개 묶음을 확인했다. 결과: `verification/v10/ux/smoke-results.json`. 홈 화면에서 버튼 텍스트 가운데 정렬과 119 빨강·112 파랑을 육안 및 픽셀로 확인했다.
- 개인정보 보호 화면의 캡처 차단을 해제하지 않았으며, 인증된 실제 차량 또는 TalkBack 사용자 시험은 수행하지 않았다. 실제 병원 투약 내역과의 일치 여부도 확인할 수 없다.
