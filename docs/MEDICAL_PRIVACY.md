## 기본 인증 경로

1. 차량 Android가 보안 화면 잠금 기능을 제공하고 PIN·패턴·비밀번호가 등록돼 있으면 시스템 자격 확인 화면을 연다. 실제 인증 성공 결과만 허용한다.
2. 시스템 인증을 제공하지 않거나 인증 화면을 실행할 수 없으면 앱 PIN을 사용한다. 처음 접근할 때 사용자가 **6~12자리 숫자 PIN을 두 번 입력**해 설정한다. 고정 기본 PIN은 없다.
3. 기존 앱 PIN이 있으면 차량 설정을 바꾸는 것만으로 우회하지 못하도록 그 PIN을 계속 요구한다. 시스템 인증 취소를 PIN 신규 설정으로 자동 우회하지 않는다.

[KeyguardManager 공식 API](https://developer.android.com/reference/android/app/KeyguardManager#createConfirmDeviceCredentialIntent(java.lang.CharSequence,%20java.lang.CharSequence)). API 28 호환을 위해 기존 시스템 자격 확인 Intent를 사용하며 deprecated 상태를 문서화했다. 차량에 없는 OEM 인증·디지털키 API는 추정 호출하지 않는다. 현재 Pleos AVD의 시스템 잠금 미등록 환경에서는 앱 PIN 경로를 검증한다.

## 표시와 동작

- 가족 목록·선택·편집, 응급카드, 의료 요약·가상 상황실·안심콜·운전자 프로필·환자 영상은 인증 후 연다.
- 인증 전 세션 화면에는 이름 대신 `선택된 탑승자 · 잠김`을 표시한다. 열람·편집·공유 조작도 인증을 확인한다.
- 인증 유효 시간은 최대 60초다. 홈 복귀·수동 잠금·앱 비활성화에서 다시 잠그고 미리보기를 숨긴다. 다른 앱에서 돌아와도 자동 해제하지 않는다.
- 민감 화면과 PIN 창에는 FLAG_SECURE로 캡처·비보안 디스플레이 공유를 제한한다. 터치 가림 방지도 적용한다. 실제 장치별 차이가 있으므로 모든 촬영·루팅 공격을 막는다고 주장하지 않는다. [Android 공식 설명](https://developer.android.com/security/fraud-prevention/activities)
- 119/112 연결 시연, 기본 의사표현, 가상 위치 공유, 공개 매뉴얼은 의료정보 잠금 때문에 중단하지 않는다. 플랫폼 주행 제한은 PIN으로 해제하지 않는다.

## 저장과 실패 처리

PIN 원문은 저장하지 않는다. 무작위 salt, PBKDF2-HMAC-SHA256(210,000회)와 Android Keystore의 비수출 HMAC 키를 사용한 검증값만 저장하고 상수 시간 비교를 사용한다. 5회 실패하면 30초부터 최대 5분까지 입력 제한을 적용하며 실패 상태는 앱 재시작에도 유지한다.

PIN 계산은 UI와 분리한다. 확인 중에도 취소하고 긴급 연결로 돌아갈 수 있다. 초기화·앱 전환·종료에서 진행 중 인증을 무효화하며, 이전 작업이 늦게 끝나도 인증·저장 상태를 되살리지 못하도록 최종 저장과 초기화를 직렬화한다. 소프트웨어 에뮬레이터에서의 인증 시간은 검증 JSON에 따로 기록한다.

저장 프로필은 Android Keystore AES-256-GCM으로 암호화한다. 기존 평문 프로필은 암호화 형식으로 옮기고 평문 항목을 제거한다. 키/암호문을 확인할 수 없으면 기존 내용을 표시하지 않는다. 인증 토큰은 메모리에만 두며 재생성에서 복원하지 않는다. saved-instance state에도 개인 ID·병력·대화·혈당·의료 공유값을 넣지 않는다.

PIN 분실 시 기존 정보를 남긴 채 우회하는 초기화는 없다. `시연 도구 → 의료정보 잠금·PIN 설정 → 저장 의료정보 삭제·잠금 초기화`는 저장한 가족·상담·PIN을 함께 지우고 APK의 가상 기본 예시만 복원한다. 차량 Android 자체의 화면 잠금은 변경하지 않는다.

v0.18의 잠금 초기화는 직접 입력한 본인·가족 건강정보를 삭제한 다음 키를 삭제한다. 데이터는 `lifelink_personal_health_v1`의 `records_cipher`에 AES-GCM으로 저장한다. 이전 `record_cipher`도 읽을 수 있으며 정상 저장 시 새 목록으로 전환한다. 입력 필드는 자동완성과 상태 저장을 끈다. 등록 연락처·관리 방식·사용자 확인 상태도 암호화 목록에 포함하며, 직접 입력한 정보는 긴급 세션이나 가상 상황실에 자동으로 포함되지 않는다. [가족 안심콜 구현 범위](SAFE_CALL_IMPLEMENTATION_V18.md)

수혜자/대리자 선택과 관리 권한 체크는 앱 내부의 사용자 확인이며 법적 대리 관계나 기관 등록 확인을 대신하지 않는다. 공식 사이트로 이동할 때는 고정 공개 URL만 전달하고 개인정보·자동 입력 데이터를 붙이지 않는다. 앱 전환 시 기존 잠금을 유지하며, 사이트 방문을 공식 가입 완료로 자동 처리하지 않는다.

Keystore 키의 하드웨어 보관·실차 보안 인증은 주장하지 않는다. [Keystore 공식 설명](https://developer.android.com/privacy-and-security/keystore). 실제 의료정보 저장을 허용하는 상용 제품에는 별도 개인정보·보안·운영 검토가 필요하다.

## 검증

MedicalPrivacyTest는 경로·PIN 형식·60초·다회 실패·저장 상태 정리를 검사한다. smoke-medical-privacy.py는 임시 QA PIN으로 설정/실패/재시작/자동 잠금/앱 전환/캡처 차단/저장 암호화를 검증한다. PIN은 로그·스크린샷·결과 JSON에 기록하지 않고 종료 시 초기화한다. 캡처가 거부되면 보호를 우회하지 않고 .capture.json으로 기록한다.
