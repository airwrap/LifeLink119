# 소방청 안심콜 로그인·차량 보관·신고 전달 검토

확인일: 2026-11-13. 현재 앱 버전: 0.18.0-demo.

## 결론

**공식 사이트에서 본인 로그인 후 등록정보를 조회하는 흐름과, 차량 내 암호화 보관·인증 후 조회는 구분해야 한다.** 전자는 사용자가 확인한 ID·문자 인증 흐름이며 후자는 앱에 구현돼 있다. 사이트에서 조회한 정보를 외부 차량 앱이 자동으로 가져오거나 119에 전달하는 공개 연계 규격은 확보하지 못했다. 다만 공식 알림마당에서 본인전송요구 절차를 새로 확인했으므로 그 절차와 기관이 승인한 연계 방식을 통해 구체화할 수 있다. 공개 API가 존재하지 않는다고 단정한 결론은 아니다.

추가로 받은 공식 입력 화면 5개와 HTML의 항목은 [공식 양식 대조·보완 기록](SAFE_CALL_FORM_AUDIT_20261113.md)에 따라 차량 보관 모델과 UI에 반영했다. 자동 로그인·자동 가져오기가 구현됐다는 의미는 아니다.

현재 구현은 공식 사이트 외부 브라우저 열기 → 본인/대리인 등록·수정 → 사용자가 차량에 필요한 정보를 직접 입력 → Android Keystore AES-GCM 암호화 → 사고 시 앱 인증 후 조회이다. 차량 저장 정보는 실제 신고나 PC 시연 서버에 전달되지 않는다. 공식 웹 로그인 성공·사이트 복귀·사용자 확인 체크를 공식 조회 성공으로 표시하지 않는다.

## 공식 자료에서 확인한 범위

- [소방청 안심콜 안내](https://www.nfa.go.kr/nfa/safetyinfo/emergencyservice/urelaxcallservice/): 본인 또는 대리인이 병력 등을 사전에 등록하고, 신고 접수 기관과 출동대가 정보를 활용하는 서비스다.
- [소방청 보도자료: 언제 어디서나 맞춤형 119 구급 서비스](https://www.nfa.go.kr/nfa/news/pressrelease/press/?cntId=2490&mode=view): 병력·수술·복약 정보를 사전 등록하는 이용 흐름을 설명한다.
- [정부 정책브리핑 이용 안내](https://www.korea.kr/news/policyNewsView.do?newsId=148896108): 등록된 전화로 신고해야 사전 정보를 활용할 수 있으며 변경 정보는 본인/대리인이 수정해야 한다.
- [공식 로그인 페이지](https://u119.nfa.go.kr/main/loginForm?menuCd=login)는 브라우저에서 ID 입력란과 로그인 메뉴를 직접 확인했다. 문자 인증 이후 본인정보 조회 흐름과 입력 항목은 사용자가 제공한 설명·화면·HTML을 추가 근거로 삼았다. 실제 ID·문자를 입력한 로그인, 제3자 제공 권한, 다운로드 형식은 검증하지 않았다.
- [공식 알림마당](https://u119.nfa.go.kr/main/loginForm?menuCd=SCSBM010000)의 2026-09-01 「개인정보의 본인전송요구에 관한 사항 알림」을 직접 열어 읽었다. 기본 등록정보와 병력·복약·알레르기·보호자 연락처를 본인에게 전송하도록 신청하는 절차가 있다. 홈페이지 문의하기 또는 국민신문고에서 전송 항목과 수령방법을 신청하도록 안내하며, 대리인의 자동화 도구 이용에는 소방청과의 사전협의 방식을 따르도록 명시한다. 동적 페이지이므로 목록에서 제목을 선택해야 상세 내용이 표시될 수 있다.

공식 안내와 공공데이터 포털을 검색했으나 외부 앱용 위임 인증, 개인 안심콜 의료정보 조회/기계판독형 내보내기, 신고 사건별 의료정보 수신 API 명세를 확보하지 못했다. 위의 본인전송요구 공지는 즉시 호출 가능한 API 명세가 아니다. 소방 통계 API도 개인 수혜자 정보 API를 대체하지 못한다.

## 제안 구조와 확보해야 할 계약

| 단계 | 제안 | 기관/OEM과 확인할 사항 |
|---|---|---|
| 평소 등록 | 정차 상태 또는 휴대전화의 공식 웹에서 본인/대리인 로그인 | 위임 인증 지원 여부, 수혜자별 대리권, 차량 앱의 이용기관 승인 |
| 가져오기 | 승인된 제공 API 또는 기관이 발행한 검증 가능한 내보내기 자료 | 실제 규격·필드·서명 검증·수신 대상·변경/철회 통지. OAuth를 지원한다고 가정하지 않음 |
| 차량 보관 | 항목별 수집 동의 후 필요한 최소 정보만 Keystore로 암호화 | 사용자/차량 소유자 분리, 가족/렌터카/양도 시 삭제, 보관 기한, 출처와 마지막 동기화 시각 |
| 사고 조회 | 탑승자 선택 → 인증 → 저장 시점과 최신성 표시 | 운전자와 환자를 별도로 식별. 에어백 신호를 자동 신원 확인이나 의료정보 잠금 해제 근거로 사용하지 않음 |
| 신고 전달 | 사건별 대상·항목·수신 기관 확인 → 별도 동의 → 승인된 전송 채널 | 실제 사건 ID, 수신 확인, 중복 전송 방지, 철회/보존 정책, 통신 장애 시 처리 |

현재는 웹 ID/비밀번호·쿠키를 차량에 수집하지 않는다. 로그인 HTML 스크래핑, WebView 자바스크립트로 병력 추출, 비공개 웹 요청 재현, 임의 OAuth/신고 API 주소를 구현하지 않았다. 이는 확보되지 않은 인터페이스를 성공하는 연동처럼 만들지 않기 위한 구현 판단이다.

## 신고 회선과 환자 식별

차량 자체 SIM, Bluetooth 연결 전화, 다른 가족 전화, 공용 전화는 안심콜에 등록한 수혜자의 번호와 다를 수 있다. 웹 로그인 계정·운전자 계정·발신 전화번호·실제 환자는 별개다. 등록번호 일치를 추측하거나 차량 사고만으로 가족 전체 병력을 전송하면 안 된다. 번호 불일치나 조회 실패는 신고 진행을 막지 않으며 상황요원에게 대상을 설명하는 경로가 필요하다.

차량에서 119 통화를 시작했다고 별도 앱 데이터가 자동으로 전달되는 것은 아니다. 공식 안내의 사전 DB 조회와 앱의 데이터 전송은 서로 다른 경로다. 의식이 없는 탑승자를 위한 인증 없는 긴급 열람은 별도 권한·동의·감사 설계가 필요한 후속 과제로 남겼다. 현재는 사고 시에도 의료정보 인증을 우회하지 않는다.

## 현재 구현과 후속 개발

| 기능 | 상태 |
|---|---|
| 공식 웹 가입·로그인·수정 안내 | 구현, 외부 브라우저 사용 |
| 직접 입력한 최대 12개 건강정보 암호화 보관 | 구현, 전체 UTF-8 JSON 400,000바이트 상한 및 저장 전 검사 |
| PIN/시스템 자격 인증 후 오프라인 조회 | 구현, 60초 후 재잠금 |
| 웹 로그인 후 자동 가져오기·주기적 동기화 | 미구현, 공식 규격·이용 승인 필요 |
| 사고 자동 감지로 신원 확인·의료정보 잠금 해제 | 미구현 |
| 실제 119 통화·문자·의료정보 전송 | 미구현, 현재 기관 연결은 모의 시연 |

민감정보 처리 근거, 수집·보관·제3자 제공 동의, 대리인 관리 권한, 의식 없는 환자에 대한 긴급 제공 정책은 실서비스 설계 때 담당 기관 및 개인정보 담당자와 확정해야 한다. 이 문서는 법적 적합성 판정이나 소방청 연계 승인서가 아니다.
