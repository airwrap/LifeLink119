# LifeLink 119 v0.7.0-demo · 차 안의 위급 상황

작업일: 2026-11-01. 기준은 CODEX_PROMPTS.md·통합 UX 지침과 사용자의 공모전 시연 요청이다. 구체적인 위험 종류를 고르는 메뉴를 추가하지 않고, **차 안의 위급 상황으로 먼저 119 상황실에 연결**하도록 구성했다. 실제 발신은 없다.

## 구현

- 홈 상단의 **119 빠른 호출**로 정차·프로필 등록·PIN·위치 확인 없이 가상 연결을 요청한다. 기존 홈의 두 대표 행동은 유지한다.
- 같은 주행 시연이 요청 중·연결됨·실패 상태라면 기존 호출을 다시 열어 중복 요청을 만들지 않는다. 실패 후 같은 호출로 재시도·취소할 수 있다.
- 위험 종류를 선택하는 문답은 없다. 기본 전달 내용은 ‘차 안의 위급 상황’이며, 구체적인 내용은 연결 후 상황실에 설명하는 흐름이다. 인원·부상 여부를 자동으로 판단하지 않는다.
- 가상 상황 전달 → 상황실 역할 확인 → 정차했다고 알림 → 안전 확보했다고 알림 → 가상 대응팀 인계 → 종료를 연결했다. 정차는 호출·상황 전달의 선행 조건이 아니다.
- 위치·차량 공유는 각각 선택하며 철회할 수 있다. 위치가 없어도 호출·전달이 가능하다. 의료정보 열람·공유는 기존 별도 인증과 동의를 따른다.
- 음성 요청은 명시적인 **예시 버튼**이다. 녹음·인식·실제 음성 상담을 구현한 것으로 표시하지 않는다.
- 실제 CarUX가 상세 조작을 제한하거나 알 수 없으면 빠른 호출·종료만 남긴다. 추가 제한 시연은 기존 제한을 강화하며, 수동 정차 상태로 실제 제한을 풀지 않는다.
- Android 화면 복원 시 연결은 유지하고 전달·안전 확인을 초기화해 재확인 안내를 표시한다. 종료·취소 시 세션 공유정보와 주행 시연 상태를 정리한다.
- 기존 매뉴얼·추가 지원·협력 차량·별도 표시 승인 흐름은 유지한다. 긴급 호출만으로 표시 승인·차량 제어가 발생하지 않는다.
- D01을 추가해 총 19개 갤러리 예시를 제공한다. 선택적인 PC 메타데이터 전송도 D01을 허용하되 실제 값·위험 설명·안전 확인은 추가 전송하지 않는다.

## 파일과 구조

`core/DrivingEmergency.kt`는 가상 안전·전달 상태 전이를 담당하고 `SessionEngine`이 연결 상태와 플랫폼 제한을 검사한다. `ExperienceStateCodec`은 고정 enum만 복원하고 허용하지 않은 필드는 거절한다. `ExpansionUi`가 공개 시연 화면과 기존 인증 화면을 분리한다. 새 권한이나 라이브 통신 연계는 추가하지 않았다.

Vehicle SDK 2.3.2, minSdk28, compile/target34를 유지했다. 서비스 버전은 code8 / `0.7.0-demo`다. 기존 실제 주행 제한 검사 `scripts/smoke-driving.py`는 보존하고, 새 기능 검사는 `scripts/smoke-driving-emergency.py`로 분리했다.

- `scripts/verify-driving-artifacts.py`는 빌드·테스트·lint 결과, 설치 검증 해시, API/버전, 불필요한 민감 권한 부재와 APK 서명을 검사한 뒤 배포 복사본을 생성한다. 결과는 `verification/v07/validation.json`이다.

발표 순서와 재현 명령은 [주행 중 긴급 호출 시연](DRIVING_EMERGENCY_DEMO.md)에 있다. APK와 로컬 검증 기록은 Git 제외 대상이며 새 PC에서는 소스로 재빌드한다.

## 확인 범위

이번 기능 검증의 ‘주행 중’은 시연 상태다. 실제 운전·실차·OEM 앱 실행 허용·음성 인식·119 접수/출동을 검증한 결과가 아니다. 허용된 실제 CarUX 값과 추가 제한 시연을 구분한다. 이전 v0.6의 실제 콜백 0→80→0 기록을 이번 APK의 재검증으로 계산하지 않는다.

기관 접수·대응팀 인계·위치·차량 데이터는 모두 가상이다. 임의 응급의료 판단이나 자동 경찰·등화 승인을 추가하지 않았다. 이전 결과는 [v0.6 구현 보고서](IMPLEMENTATION_REPORT.md)에 남겼다.
