# LifeLink 119 · 옆 차가 첫 도움으로

작성일: 2026-10-25 · v0.4.1-demo

## 검증하려는 아이디어

가족과 이동 중 위급상황이 생겼을 때, 정규 구급대가 도착하기 전 가까운 차량과 사람이 **잠시 응급협력 역할을 맡도록 연결**한다. 차량의 위치뿐 아니라 참여 의사, 교육·장비 조건, 상황실 조율, 종료와 인계를 함께 설계한다. 비상표시는 그 임무를 주변에 알리는 하나의 수단이다.

이번 PoC는 이 아이디어를 화면과 상태 전이로 직접 실행한다. 색상·점멸 방식은 실험용 모형이며 실제 제동등이나 차량 버스에 연결하지 않는다. 앱이 협력 임무를 부여하는 것과 법률상 차량 지위를 정하는 것은 서로 다른 검증 과제다.

색깔 유도선의 도입 경험에서 가져올 점은 **작게 실험하고, 효과와 부작용을 측정하고, 근거를 가지고 확대하는 과정**이다. KTV의 도입 과정 소개도 시도와 효과 확인, 제도화·확대를 다룬다. 이 사례 자체가 다른 등화장치의 효과나 적용 가능성을 입증하는 것은 아니다. [KTV의 노면 색깔 유도선 소개](https://www.ktv.go.kr/content/view?content_id=716253&unit=266)

가까운 교육 이수자에게 도움을 요청한다는 발상에는 연구할 근거가 있다. 휴대전화로 교육받은 자원봉사자를 연결한 무작위 연구는 구급대 도착 전 목격자 CPR 시행 비율을 평가했다. 이는 협력 네트워크 가설의 참고 근거이며, 이번 앱·차량 표시의 생존 효과를 입증한 연구는 아니다. [NEJM, Mobile-Phone Dispatch of Laypersons for CPR (2015)](https://www.nejm.org/doi/full/10.1056/NEJMoa1406038)

## 지금 실행할 수 있는 흐름

1. 요청자가 고정 가상 상황을 고르고 모의 위치 공유에 명시적으로 동의한다. 기본값은 OFF다.
2. 119 역할이 상황을 확인한다. 응급 대응이 진행되는 기존 시나리오를 유지한다.
3. 참여 동의·교육·가용 조건을 충족한 가상 차량을 상황실 역할이 초대한다. 가장 가깝다는 이유만으로 자동 배정하지 않는다.
4. 차량 역할이 자발적으로 수락하거나 거절한다. 거절하면 다른 적합 차량을 검토할 수 있다.
5. 119 역할이 해당 차량에 300초의 응급협력 임무를 부여한다.
6. 임무와 별도로 119 또는 112 역할이 최대 120초의 비상표시를 승인한다. 승인 ID는 요청·차량·임무 세대·승인 회차에 결합한다.
7. 협력 차량 역할이 이동 중에도 승인된 화면 표시를 켜고 현장 지원을 시연한다.
8. 구급대 인계·참여 철회·기관 역할 철회·임무 만료 시 표시를 종료한다. 통신 실패·화면 비활성에서도 화면 표시를 끈다. 이동 상태 선택은 표시 중단 조건이 아니다.

기관 역할은 **인증 없는 localhost 역할 연습**이다. Android에는 기관 승인 버튼을 두지 않고 PC의 역할 화면과 연동한다. 112 역할은 표시 승인·철회를 시연하며 의료 협력 임무 부여는 119 역할로 구분한다.

## 세 가지 고정 실험 조건

| 조건 | 구급대 도착 가정 | 협력 차량 첫 도움 가정 | 비교 의미 |
|---|---:|---:|---|
| 가까운 차량이 먼저 돕는 상황 | 480초 | 이동 150초 + 조율 45초 = 195초 | 285초 먼저 도울 **기회 가정** |
| 구급대가 더 빠른 상황 | 120초 | 195초 | 시간 이득 0, 구급대가 75초 먼저 |
| 참여 가능한 차량이 없는 상황 | 480초 | 없음 | 기존 구급대 대응 시나리오 유지 |

차량 B는 이동 가정 40초로 가장 가깝지만 교육 조건이 맞지 않는다. C는 90초지만 참여 동의가 없다. A는 150초·참여 동의·CPR 교육·AED 보유를 가정하고, D는 270초·참여 동의·CPR 교육을 가정한다. 이것은 실제 자격·장비 확인 기능이 아니다.

계산은 `max(0, 구급대 도착 가정 - (협력 차량 이동 가정 + 조율 가정))`이다. 협력 차량의 도착은 환자 이송이나 전문 치료 완료를 의미하지 않는다. 구급차를 취소·지연시키거나 환자를 일반 차량으로 이송하는 동작은 구현하지 않았다.

화면 조작 시간은 서버의 단조 시계로 따로 기록한다. 운영자 버튼을 빨리 누른 시간이 실제 현장 도착시간으로 계산되지 않는다. 실험 기록 JSON에는 가정·역할 동작·경과시간과 `actualResponseTimeMeasured:false`, `clinicalOutcomeMeasured:false`를 보관한다. 이번 결과를 몇 명의 생명을 살린다는 수치로 환산하지 않는다.

## 다음 단계의 실험 계획

| 단계 | 실행 내용 | 측정할 항목 | 다음 단계로 넘어갈 근거 |
|---|---|---|---|
| 1. 현재 화면 PoC | Pleos AVD·웹에서 요청/수락/승인/철회/인계, 통신 장애와 만료 반복 | 흐름 성공 여부, 실제 조작 경과, 오류 복구, 부적격 배정·승인 전 표시 발생 여부 | 자동 검사 통과와 재현 가능한 기록 |
| 2. 실내 벤치·마네킹 | 별도 화면 또는 전용 모형 표시장치, 교육받은 참가자와 응급대응 전문가가 역할 연습 | 신호 의미 이해, 기존 제동등·방향지시등과 혼동, 조율 소요, 마네킹 지원·인계 품질 | 신호 오인·조작 부담을 줄인 설계와 전문가 검토 |
| 3. 폐쇄 시험장 | 관계기관·제조사와 설계한 통제 환경에서 일반 차량 역할과 구급대 역할 연습 | 요청부터 첫 적절한 도움까지 실측, 기존 대응 지연 여부, 잘못된 접근·오인 비율, 임무 종료 전달 | 사전에 정한 수락 기준, 중단 기준, 비교 조건을 충족 |
| 4. 공식 실증 검토 | 실측 결과로 참여·자격 확인, 기관 인증, 장치 규격, 운영 책임과 제도 절차 구체화 | 안전성·실효성·현장 수용성과 운영 가능성 | 해당 범위의 공식 실증 절차와 승인 |

실내·폐쇄 시험에서는 표시가 없는 조건과 후보 표시 조건을 비교하고 시나리오 순서를 바꾼다. 낮·밤·가림 상황, 색각 차이, 청각 신호 없이도 이해되는지 함께 본다. 빨간색을 최종 규격으로 먼저 확정하지 않고 **인지성과 오인 가능성**을 측정한다. 실제 비상 신고·환자·일반 도로를 이용하지 않는다.

실험 전 성공 기준과 중단 기준을 수치로 합의한다. 예를 들어 승인 전 표시·철회 후 지속·기존 대응 취소가 발생하면 해당 시험을 중단하고 원인을 수정한다. 시간 단축은 기존 대응의 지연이나 부적절한 처치 증가 없이 관찰되는지 비교한다. 임상 효과 평가가 필요해지면 의료진과 별도의 연구 설계를 진행한다.

## 기술 경계와 확장 지점

- Android: `core/CooperationPolicy.kt`가 표시 조건을 판단하고 `data/CooperationGateway.kt`가 debug의 고정 loopback API만 호출한다. `MainActivity`는 요청자·협력 차량 화면을 제공한다.
- 서버: `console/cooperation.py`가 고정 카탈로그, 적합성, 역할별 순서, 유효시간과 기록을 담당한다. 기존 상담 세션과 별도 저장소를 사용하며 50건·60분 후 제거한다. 재시작하면 메모리 기록이 사라진다.
- 웹: `/cooperation`에서 전체 역할을 연습하고 `/cooperation?run=<실험ID>&view=beacon`에서 별도 화면 표시를 연습한다. JSON 내보내기는 사용자가 파일로 저장하는 기능이다.
- 표시: 동일 승인 재전송으로 시간이 늘어나지 않는다. 만료 뒤 새 승인은 새로운 회차 ID를 발급한다. 새로고침·연결 실패·백그라운드에서는 최신 서버 상태 확인이 필요하다. 정차 확인을 요구하지 않는다.
- 차량: 공식 Pleos Vehicle SDK 2.3.2와 기존 조회 권한을 유지한다. 등화·사이렌 제어 API와 권한을 추가하지 않았다. 실제 속도/기어 기반 제한, 기관 인증·서명된 승인, 자격·장비 검증은 후속 연동 과제다.

현행 도로교통법 시행령 제2조 제2항 제3호에는 위급한 환자 등을 운송 중인 자동차에 관한 긴급자동차 간주 규정이 이미 있다. 이를 이번 소프트웨어가 임의로 허가하거나 적용 여부를 판정하지 않는다. 표시장치와 운영 절차는 후속 실증 범위에 맞춰 별도로 검토한다. **현재 화면 PoC를 진행하는 데 이 검토를 선행 중단 조건으로 두지 않는다.** [도로교통법 시행령 제2조](https://www.law.go.kr/법령/도로교통법시행령/제2조)

## 실행

`Start-Local-Demo.cmd`로 서버를 켜고 <http://127.0.0.1:8781/cooperation>을 연다. Android는 최신 debug APK를 설치하고 `adb reverse tcp:8781 tcp:8781` 연결 후 홈의 **옆 차가 첫 도움으로 · 응급협력 차량 PoC**를 선택한다. 기관 역할은 PC 웹에서 해당 실험 ID를 열어 진행한다.

Android와 PC를 함께 체험하는 순서:

1. 앱에서 바로 또는 이동 중 상황 선택 → 가까운 차량 시나리오 → 모의 위치 공유 동의 → **주변 차량 도움 요청**.
2. PC 웹에서 **새로고침** → 앱과 같은 POC ID 선택 → **선택한 실험 열기**.
3. PC의 119 역할에서 **상황 확인 → 가상 협력 차량 A 선택 → 선택 차량 초대**.
4. 앱에서 **협력 차량 역할로 보기 → 자발적 참여 수락**.
5. PC에서 **응급협력 역할 부여 → 비상 표시 승인**. 표시 승인만 112 역할로 바꾸어 비교할 수도 있다.
6. 앱에서 **승인된 응급협력 표시 켜기 → 현장 도착·초기대응 지원 시연**.
7. PC에서 **구급대 인계 완료**. 앱과 웹의 표시 OFF와 임무 종료를 확인하고 JSON 기록을 저장한다.

웹만 사용할 때는 한 화면에서 각 역할을 차례로 조작한다. 정차 확인 없이 차량 역할의 동작을 사용할 수 있다. 실험은 수락 전 거절하거나 참여 후 철회할 수 있다. 실제 움직이지 않아도 현장 도착·지원 역할을 버튼으로 시연할 수 있으며 이 조작 경과는 실제 이동시간으로 취급하지 않는다.
