# LifeLink 119 v0.6 · UX 명세

2026-10-28 / 기존 Kotlin Views·단일 MainActivity에 점진 적용.

## 의도에서 연결로

홈의 큰 행동은 `지금 긴급해요`, `상담받고 싶어요` 두 개다. 가족정보는 작은 보조 진입이며 차량·설정·갤러리는 더보기에 있다. 모든 화면 상단에 **시연 모드 | 실제 신고·상담 연결 아님**, 홈·긴급 연결 경로를 둔다.

| 진입 | 두 번째 선택 | 목적 |
|---|---|---|
| 지금 긴급해요 | 119 구조·구급 연결 시연 | 긴급 구조·구급 요청 |
| 지금 긴급해요 | 112 긴급신고 연결 시연 | 범죄·폭력·교통 위험 |
| 상담받고 싶어요 | 119 응급의료상담 | 전문 상담원의 안내 |
| 상담받고 싶어요 | 109 심리위기 상담 | 프라이버시를 지키는 상담 |

긴급 시연 요청까지 두 탭이며 프로필·동의·상황 문답을 앞세우지 않는다. 실제 기관으로 연결하는 기능은 없다. OS가 주행 중 앱 자체를 차단하는 경우 이를 우회하지 않는다.

## 연결 이후

`요청 중 → 가상 상담원 응답 → 추가 지원 진행 → 완료/취소`를 동일 세션 모델로 표시한다. 실패 시 다시 시도/취소를 제공한다. 원하는 경우에만 도움받는 사람과 상황을 바꾼다. 상황을 갤러리에서 실행하면 가상 프로필이 미리 선택되지만, 의료정보 공유는 여전히 별도 동의가 필요하다.

`ContextualActionResolver`가 기관·상황·접근성 선호·플랫폼 제한으로 최대 세 개의 기본 행동을 정한다. 나머지는 `추가 지원`에 둔다. 청각은 문자/수어, 언어는 의사표현, 시각은 음성 모형, 인지는 쉬운 안내, 이동은 승하차 도움을 먼저 제시한다. 선호는 기능 접근 자격이 아니다. 109에서는 프라이버시/문자/요약이 우선이며 보호자를 자동 통보하지 않는다. 112는 119 과정을 거치지 않는다.

갤러리: `더보기 → 설정·시연 도구 → 시나리오 갤러리`. S01~S14, E01~E04는 JSON 한 곳에서 읽으며 화면을 복제하지 않는다.

## 동의와 데이터 정리

- 실제 개인정보 입력 모드를 제공하지 않는다. 별명·연령·병력·약·알레르기·임신·접근성·보호자는 고정된 가상 선택지다. 연락처는 전화번호가 아닌 `DEMO-CONTACT` 식별자다.
- 가족 목록·선택·편집·의료 카드는 시스템 자격 확인 또는 앱 PIN 인증 후 연다. 인증 전 탑승자 이름도 가린다. 최대60초·홈 복귀·앱 전환에서 다시 잠그며 민감 화면 캡처를 제한한다. 저장 가상 프로필은 Keystore 암호화하고 개인 정보는 saved-instance state에 넣지 않는다. 상세 정책은 [의료정보 보호](MEDICAL_PRIVACY.md)를 따른다.
- 카드의 각 항목은 독립 동의다. 처음에는 선택되지 않는다. 체크만으로 전송하지 않으며 `선택 정보 모의 공유`로 앱 내 상황실에 반영한다. 체크 해제/전체 철회로 상황실 데이터도 제거한다.
- 환자 변경은 개인 의료·대화·영상·안심콜·경찰·목적지 상태를 정리하고 발견시각·가상 혈당을 초기화한다. 위치/차량 동의만 유지한다. 상황 변경은 요약/영상/운송·경찰 상태를 초기화한다.
- 영상은 소스 선택 요청 → 합성 영상 사용 동의 → 공유 시작 → 중단이다. 실제 촬영·전송은 없다. 프리뷰는 버튼으로 바뀌는 합성 도형이며 상시 녹화나 재생을 하지 않는다. 앱 비활성화 시 미리보기를 숨긴다.
- 종료/취소 시 세션의 공유값·개인 연결·대화·영상·혈당·목적지·동의를 정리한다. 프로필 저장은 별도 기능이며 가족 화면에서 삭제/복원한다. 동작 기록에는 이벤트 코드만 남긴다.
- 기본 모의 센터는 메모리를 공유하므로 완전 오프라인이다. 선택적 PC 게시도 debug의 localhost로 상태·항목 이름만 보내며 의료내용/대화/좌표/영상은 보내지 않는다. PC는 수동 스냅샷임을 표시한다. 철회 실패는 재시도를 제공한다.

## 주변 차량 협력과 표시 모형

추가 지원 또는 시연 도구에서 같은 임상 판단 없는 연결 세션을 사용한다. `가상 위치 동의 → 별도 도움 요청 동의 → 가상 119 역할 상황 확인 → 조건에 맞는 차량 초대 → 차량의 자발적 수락/거절 → 300초 가상 임무` 순서다. 참여 동의·교육·가용 조건이 없는 차량은 가까워도 초대할 수 없다. 참여 차량이 없거나 구급대가 더 빠른 대조 조건도 제공한다.

표시는 임무와 별개로 `119/112 역할 선택 → 비상상황 확인 → 최대120초 승인 또는 거절 → 사용자가 모형 시작`이 필요하다. 승인 ID는 해당 가상 차량·임무·승인 회차에 묶인다. 화면에만 점멸하며 실제 차량 등화는 변경하지 않는다. 법적 지위·도로 통행 권한은 부여하지 않는다.

승인 만료·임무 만료·철회·인계·대상 변경·위치 동의 철회는 표시를 중단한다. 앱 비활성화나 다른 화면 이동 시 표시를 숨기고 복귀 후에도 자동 재시작하지 않는다. 재생성 시 임무·승인을 복원하지 않아 새 동의/승인을 요구한다. 시연 경과 시간은 종료 시 고정하며 고정 도착 가정과 분리한다. 기존 온라인 협력 모듈도 기존 5개 흐름 도구에서 유지한다.

## 차량 제한과 접근성

실제 `CarUxRestrictionsManager`의 known/DO 요구 및 ActiveRestrictions를 적용한다. 상태 미확인 AAOS는 보수적으로 상세·영상·긴 목록을 잠근다. 비 AAOS는 `NOT_AVAILABLE`로 명시하는 로컬 데모다. 추가 제한 시연은 실제 제한에 OR 결합하며 실제 제한을 해제할 수 없다. 기존 수동 이동/정차 설정은 시나리오 문맥이며 별도의 정차 확인 게이트가 아니다.

영상/수어는 NO_VIDEO, 문자는 NO_TEXT_MESSAGE, 상세 프로필·카드·요약·EV·설정은 NO_SETUP/NO_KEYBOARD 및 DO 요구에 따라 제한한다. 긴 목록은 LIMIT_CONTENT에 따라 숨긴다. 실제 OS의 화면 차단은 앱의 버튼 정책보다 우선한다. 임의 DO 메타데이터는 추가하지 않았다.

기본 버튼 64dp, 체크 항목 56dp, 슬라이더 48dp 이상. 고대비와 문자 라벨을 사용하고 화면 순서대로 접근성 노드를 만든다. 큰 글씨 설정 및 프로필별 큰 글씨/쉬운 안내를 제공한다. 좁은 창은 두 열을 한 열로 바꾸고 상단 긴급/이전 행을 분리한다. 실제 TalkBack 낭독 품질·OEM DrivingView 승인·실차 주행 안전은 별도 검증 대상이다.

시연 도구의 520dp 미리보기는 앱 내부 컨테이너 너비를 제한해 실제 좁은 창과 동일한 배치 분기를 검사한다. 원래 차량 창 크기를 바꾸거나 플랫폼 주행 제한을 우회하지 않는다. OEM 창 전환/세로 화면 전체 인증과는 구분한다.
