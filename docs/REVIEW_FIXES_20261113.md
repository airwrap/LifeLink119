# 분석 반영 기록 · 2026-11-13

원본 마이그레이션 패키지에서 소스를 수정했다. 이 작업 디렉터리에는 Git 메타데이터가 없어 커밋이나 LFS 이력 변경은 하지 않았다. 앱 버전은 0.18.0-demo를 유지했다.

## 우선 결함 1~4

| 항목 | 수정 |
|---|---|
| 1. 매뉴얼 복귀 후 PIN 무응답 | Activity 전경과 새 UI 가시성을 `UiPresence`로 분리. 레거시 도구는 UI만 숨기며 홈 복귀 시 다시 표시 상태를 설정한다. 실제 백그라운드에서는 계속 잠근다. |
| 2. 큰 건강정보 영구 잠김 | `MedicalStoragePolicy`가 UTF-8 평문 400,000바이트와 GCM IV·태그·Base64 한도를 단일 정의. codec과 암호화 모두 저장 전 검사하고 복호화도 같은 한도를 사용한다. 기존 40KB 초과 저장본도 이 한도 내이면 읽을 수 있다. 초과 저장 실패 시 기존 암호문을 덮어쓰지 않는다. |
| 3. 편집 입력 유실 | `HealthEditorDraft`를 Activity 메모리에 유지. TextWatcher로 입력 즉시 갱신하고 검증 오류는 해당 상태 문구만 바꾼다. 인증 만료·화면 재구성·재인증 시 초안을 복원한다. 저장·취소·홈·다른 대상 편집·종료 시 폐기하며 saved state/로그/디스크에 저장하지 않는다. |
| 4. 삭제형 QA 가드 | `QaAvdGuard`에 전용 AVD 목록, 기존 PIN/신·구 의료정보/가상 프로필 검사, 현재 사용자·부팅 ID 검증 추가. 일상 Pleos AVD는 거부한다. 초기 검사를 통과한 실행만 정리하며 정리 직전 대상이 같음을 다시 검사한다. `assert`에 의존하지 않는다. |

## 견고성·보안 5~10

- **5:** PIN 재시도에 `elapsedRealtime`과 `BOOT_COUNT`를 사용한다. 부팅이 바뀌면 미완료 제한 시간을 다시 적용한다. PIN 입력 뷰의 상태 저장도 차단했다.
- **6:** core가 의료 항목 공유 시 인증·60초 유효기간·주행 제한을 검사한다. 혼합 항목 요청은 전체를 거부해 일부 데이터만 먼저 공유되는 것을 막는다. 의료정보 없이 가상 위치·차량 상태를 선택 공유하는 흐름은 유지한다.
- **7:** SDK 작업을 IDLE/BUSY/STALLED로 구분한다. 초기화가 실제로 멈춘 경우 타임아웃 이후에는 계속 BUSY를 반환하지 않고 명시적 서비스 불가를 반환한다. 무응답 SDK를 강제 종료하거나 작업 스레드를 무한 생성하지 않는다. 원래 작업이 반환하면 재조회할 수 있고, 영구 멈춤에는 앱/서비스 재시작이 필요하다. 미지원 값을 성공값으로 만들지 않는다.
- **8:** `DemoProfileId`로 프로필과 안심콜 ID 검증을 통일했다. 삭제 후 추가된 13 이상 ID를 허용하며 활성 프로필 수 12개 상한과 구분한다.
- **9:** 주야간·회전·화면 크기 구성 변경을 Activity에서 처리하고 다시 렌더한다. 메모리 세션/초안은 보존하지만 프로세스 종료 후 개인정보 복원은 하지 않는다.
- **10:** 콘솔 초기화가 세션·협력·확장 스냅샷/철회 기록을 모두 지운다. timeline은 계약의 최근 10개로 제한하고 표시 승인 ID는 별도 증가 순번을 사용한다. 협력 철회·표시 중단의 선행 상태를 검사한다. 500 오류는 예외 유형과 코드 위치를 남기되 본문·헤더·예외 메시지는 기록하지 않는다.

## 안심콜 연계

[공식 자료와 구현 가능성 검토](SAFE_CALL_WEB_INTEGRATION_REVIEW.md)를 추가했다. UI도 공식 로그인 후 자동 가져오기와 신고 자동 전달이 아직 제공되지 않음을 설명한다. 공식 인증·조회·신고 API가 확보되지 않아 임의 로그인 폼, HTML 추출, 자동 전송은 구현하지 않았다. 기존의 외부 공식 사이트 안내와 인증 후 기기 암호화 보관·조회가 현재 구현 범위다.

## 검증 결과

- Kotlin 단위 테스트 **218개 통과**: 12개 한글 최대 길이 레코드, GCM 정확한 바이트 경계/초과, 초안 유지, 인증 만료·잠금·주행 제한 공유 거부, 프로필 13 선택, 재부팅 PIN 제한, SDK 작업 격리 회귀 포함.
- `spotlessCheck`, `assembleDebug`, `testDebugUnitTest`, `lintDebug`, `assembleRelease`, `assembleDemo`, `lintDemo` 통과.
- 콘솔 Python **73개 통과**, QA 가드 **6개 통과**. 같은 가드 6개를 `python -O`에서도 통과. JSON 계약 검사 PASS.
- 공식 Pleos **2560×1440 실제 UI 검사 17개 통과**. 매뉴얼 → 홈 → PIN 해제, 입력 검증 실패, 주야간 변경, 60초 잠금과 재인증 후 초안 복원, 가족별 보관·삭제를 확인했다. 임시 PIN/건강정보 정리도 통과했다. 실행 결과는 `verification/v18/native-safe-call.json`, 공개 홈 캡처는 패키지 옆 `.tools/logs/qa-home-2560.png`에 기록했다. 생성 증빙은 문서 링크의 필수 의존성이 아니다.
- 환경변수가 없는 별도 작업 폴더에서 절대 경로로 `Build-And-Test.cmd`를 실행해 JDK/SDK 폴백과 현재 폴더 독립 실행을 확인했다. 실제 APK 메타데이터에서 demo 비디버그와 release INTERNET 권한 제외도 확인했다.
- 전체 영상 재출력·실차·실제 소방청 로그인·기관 데이터 가져오기/전송은 검증하지 않았다.

실행 상세 로그는 패키지 옆 `.tools/logs/review-build.log`, `.tools/logs/qa-safe-call.log`에 남긴다. 기존 일상 AVD와 8781 서버는 이 작업의 데이터 삭제/재시작 대상으로 사용하지 않았다.

검증 종료 후 이번에 생성한 QA AVD는 종료하고 Android SDK의 `avdmanager delete avd --name LifeLink119_QA_API_34`로 정리했다. 필요하면 `scripts/start-qa-emulator.ps1`로 다시 생성할 수 있다. 기존 `emulator-5580`은 계속 실행 중이다.
